## Why this needs Cory

Whether real collaborations may run on the product before the public launch, and on what conditions.

- Does "arrive substantially whole" apply to the public launch only, so that private use by Cory's own network before then is acceptable?
- If private real use is acceptable: for which scenario, with which people, and what must be true first? The candidate prerequisites are in `planning/F-first-slice.md`: releases where triggered, adult assurance, truthful identity claims, record access and recovery, retention, legal review where flagged.

A working demonstration is not permission for real use.

## Cory's answer

Direct ruling — 2026-10-09 and 2026-10-14/15. Source: [`2026-10-09-15-cory-reconciliation.md`](2026-10-09-15-cory-reconciliation.md) (C1).

**Real use before the public launch is allowed, in sequence:**

1. **Exhaustive synthetic scenario testing** — every combination worth exercising.
2. **Then real use by Cory's own network**, which doubles as warm-network seeding.

"This isn't really a subjective app": the rules are defined, so alpha and beta are for **bugs, aesthetics, workflow and UX simplicity**, not for discovering what the product is.

**Product authorization is not Gate 2.** This answers the product question in this file. Gate 2 (real use by real people) still requires the real-use prerequisites in `planning/F-first-slice.md` for the named scenario, and is still blocked by:

- counsel-dependent parts of D08 (which templates need legal review) and D09 (retention, statutory erasure);
- unfinished implementation: there is no real participant flow, credential, verification, signing journey, artifact or record access yet;
- step 1 above, exhaustive synthetic scenario testing, which has not happened.

A working synthetic demonstration is still not permission for real use.
